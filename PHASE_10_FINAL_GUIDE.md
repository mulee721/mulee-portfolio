### Option 2: MongoDB Atlas (Cloud)

**Step 1: Create Cluster**
1. Go to https://www.mongodb.com/cloud/atlas
2. Sign up / Log in
3. Create new project
4. Create database cluster (free tier: M0)
5. Wait 5-10 minutes for deployment

**Step 2: Create Database User**
1. In Atlas Dashboard → Security → Database Access
2. Click "Add New Database User"
3. Username: `admin`
4. Password: Generate secure password
5. Database User Privileges: Atlas Admin
6. Create user

**Step 3: Whitelist IP Address**
1. Security → Network Access
2. Click "Add IP Address"
3. Choose "Allow access from anywhere" (for development)
4. Or specify your IP: `1.2.3.4/32`

**Step 4: Get Connection String**
1. Clusters → Connect
2. Choose "Drivers"
3. Select "Node.js"
4. Copy connection string:
   ```
   mongodb+srv://admin:<password>@cluster0.xxxxx.mongodb.net/mulee?retryWrites=true&w=majority
   ```

**Step 5: Update Environment Variables**

Edit `backend/.env.local`:
```
MONGODB_URI=mongodb+srv://admin:YourPasswordHere@cluster0.xxxxx.mongodb.net/mulee?retryWrites=true&w=majority
```

**Step 6: Test Connection**
```bash
cd backend
npm run prod
# Should show:
# ✅ Default admin initialized
# ✅ Server started successfully
```

## Deployment Guides

### Deployment Option 1: Railway (Easiest)

**Why Railway?** Simple Git-based deployment, MongoDB integration, free tier available

**Setup:**
1. Go to https://railway.app
2. Sign up with GitHub
3. Create new project → "Deploy from GitHub"
4. Select your Mulee Portfolio repo
5. Configure services:

**Backend Service:**
- Framework: Node.js
- Build: `npm install && npm run build`
- Start: `npm run prod`
- Port: 3000
- Environment Variables:
  ```
  NODE_ENV=production
  JWT_SECRET=generate-random-key-64-chars-here
  MONGODB_URI=provided-by-railway
  ADMIN_EMAIL=admin@portfolio.com
  ADMIN_PASSWORD=strong-password-here
  CORS_ORIGIN=https://admin.yourdomain.com,https://portfolio.yourdomain.com
  ```

**MongoDB Service:**
- Add MongoDB plugin from "Marketplace"
- Auto-connects, MONGODB_URI injected automatically

**Admin Dashboard Service:**
- Framework: Node.js/Vite
- Source: `/admin` directory
- Build: `npm install --legacy-peer-deps && npm run build`
- Start: `npm run preview`
- Environment:
  ```
  VITE_API_URL=https://backend-railway-id.railway.app/api
  ```
- Custom domain: `admin.yourdomain.com`

**Deploy:**
```bash
# Railway auto-deploys on git push
git add .
git commit -m "Deploy to production"
git push origin main
```

**Cost:** Free tier includes 512MB RAM, $5/month for additional services

Create `Dockerfile` in project root:
```dockerfile

# Build
```

```bash

docker tag mulee-portfolio:latest \
  123456789.dkr.ecr.us-east-1.amazonaws.com/mulee-portfolio:latest

# Push to AWS ECR
aws ecr push 123456789.dkr.ecr.us-east-1.amazonaws.com/mulee-portfolio:latest

# Deploy to ECS via AWS Console or CLI
aws ecs update-service --cluster production --service mulee-backend --force-new-deployment
```

## Troubleshooting

### MongoDB Connection Issues

**Error: "connect ECONNREFUSED"**
```
Solution:
1. Verify MongoDB is running: mongosh
2. Check MONGODB_URI in .env.local
3. If using Atlas: verify IP whitelisted
4. If using local: mongod --version && brew services list
```

**Error: "authentication failed"**
```
Solution:
1. Verify username/password correct
2. Check authentication database: ?authSource=admin
3. For Atlas: use mongodb+srv:// protocol
4. Test credentials separately:
   mongosh "mongodb+srv://user:pass@cluster.mongodb.net/mulee"
```

### JWT Token Issues

**Error: "Unauthorized" on protected routes**
```
Solution:
1. Verify token in localStorage: 
   localStorage.getItem('authToken')
2. Check token expiration (JWT decode)
3. Verify Authorization header: Bearer {token}
4. Check JWT_SECRET matches between frontend request and backend
```

**Error: "Invalid token"**
```
Solution:
1. Re-login to get fresh token
2. Check JWT_SECRET changed (invalidates all tokens)
3. Verify token not corrupted in transmission
```

### API CORS Issues

**Error: "Access to XMLHttpRequest blocked by CORS"**
```
Solution:
1. Verify frontend URL in CORS_ORIGIN
2. Restart backend after changing CORS_ORIGIN
3. Check vite proxy configured:
   proxy: { '/api': { target: 'http://localhost:3000' } }
```

### File Upload Issues

**Error: "EACCES permission denied ./uploads"**
```
Solution:
1. Create uploads directory: mkdir uploads
2. Set permissions: chmod 755 uploads
3. Check disk space: df -h
4. Verify file size < MAX_FILE_SIZE (50MB)
```

**Error: "File type not allowed"**
```
Solution:
1. Check ALLOWED_FILE_TYPES in .env
2. Verify file MIME type correct
3. For images: use png/jpeg/webp only
4. For documents: use pdf only
```

### Performance Issues

**Slow dashboard loading**
```
Solution:
1. Check MongoDB indexes created
2. Reduce initial data fetch (pagination)
3. Enable browser caching
4. Check network tab for slow endpoints
```

**High memory usage**
```
Solution:
1. Restart application
2. Check for memory leaks in monitoring
3. Reduce simultaneous connections
4. Implement connection pooling
```

### Deployment Issues

**Railway deployment fails**
```
Solution:
1. Check build logs in Railway dashboard
2. Verify package.json scripts are correct
3. Check environment variables set
4. Ensure repo has .env.local removed (use Railway UI)
```

**Heroku slug too large**
```
Solution:
1. Remove node_modules: git rm -r node_modules
2. Add to .gitignore
3. Remove large files from git history
4. Deploy: git push heroku main
```
